## 7. Rehearsal notes (2026-10-07)

- Rewrite done with Drizzle (`lib/schema.ts` mirrors the imported tables; RLS policies became explicit
  `where` clauses, e.g. public editorial reads filter `published = true`). The Supabase policies are still
  in the database: the first `pnpm db:push` will offer to drop them and disable RLS. That is expected.
- Storage: `dbm storage public warszawski` was run; `S3_PUBLIC_BASE_URL` is in `.env.local` and must be
  added to Vercel at cutover (it is not part of `dbm env`). Uploads go to `product-images/<uuid>.<ext>`.
- Stored image URLs were rewritten to the dbm host with `pnpm storage:rewrite-urls`. **Re-run it right
  after cutover**: the cutover re-copies the Supabase rows, which still hold the old URLs. Reads also map
  legacy URLs on the fly (`lib/storage/legacy-url.ts`), so nothing breaks in between.
- Users: `pnpm users:migrate .dbm-users.csv` is the Node-flag form the cutover needs (the project is CJS).
- `tools/gads/push_to_supabase.py` (gitignored, cron) now writes to dbm Postgres via `DATABASE_URL`.
- Remove `*.supabase.co` from `next.config.ts` remotePatterns once the URL rewrite has run after cutover.
